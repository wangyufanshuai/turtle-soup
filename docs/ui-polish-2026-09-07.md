## 截图驱动的修正

1. 证据浮层被粘性导航遮挡：改为原生 dialog，检查焦点循环、Escape 和关闭后焦点恢复。
2. 手机原生 dialog 默认最大宽度造成边缘空隙：显式约束宽度，并修正小屏 scrollbar gutter。
3. 连续阅读后键盘焦点跳回关闭按钮：保留翻页方向，让键盘继续阅读下一份。
4. 纸色回答区的上下文文字对比不足：改为深色正文与清晰的提示边线。
5. 推理板头部说明和事件库占用太多垂直空间：折叠说明、桌面并排、手机选卡后移交槽位焦点。
6. 320px Windows 窗口出现整页横向滚动：发现 `body` 的 320px 最小宽度没有扣除原生滚动条，最终改为可收缩布局。保留推理板切换区自身的横向滚动。复核时比较 `scrollWidth` 与 `clientWidth`，不能只与 `innerWidth` 比较。

较早 `release-*` 的 320px 截图保留了第 6 项问题；最终 `narrow-*` 是修复后的证据，没有覆盖旧图。

## 下一轮开发顺序

### 第一轮：先让 C61/C84 的公开材料足以支撑推理（TS-015）

目前“来源材料显示某对象在该阶段可复核”这类概括仍然偏空泛。本轮改善了材料的呈现，但没有把缺少事实的内容改写成未经验证的新真相。下一轮应创建独立内容版本提案与素材草稿，不改冻结基线。

- C61：逐条建立“玩家能看见的测量事实 → 可排除的解释 → 所需证明关系”对照；校准和物料推理需要真实可读的测量记录、单位和误差说明，避免只凭事件编号填槽。
- C84：用可核对的记录区分接收命令、执行完成、审计写入；列明每张板使用的公开事实、关系依据和仍可成立的替代解释。
- 交付版本差异、旧存档读取策略、公开材料充足性检查，以及不依赖作者配方的推理路径审查。没有真人也可以推进内容制作和矛盾审查。

### 第二轮：补全实际操作家族（TS-013/014）

在内容依据明确后，完善身份、空间、时间、因果等操作的区别；选择代表案做“空白 → 错误 → 修正 → 撤销 → 刷新 → 证明”的键盘与触控等价流程。不要仅换板面名称或装饰图。同步处理事件库检索零结果、长名称、更多关系和多次撤销等边界。

### 第三轮：统一剩余案件的呈现与制作质量

按季审查公开文案、证据观察、示意图标签和现场入口。将四案的排版规范应用到共享界面后，针对长文本、重复材料标题和不同素材比例补代表截图；逐步替换含混的程序化材料描述，并将新内容留在独立版本中评审。

### 第四轮：发行验收

完整执行同一发行构建的跨引擎、离线启动/恢复、AI 失败关闭和独立制品检查。当前仍是开发版本，旧 v2.12 的完整发布门禁与 18 项调查矩阵不变；不以本轮 UI 检查替代它们。

正式 Fun Gate 人数仍为 0。后续真人评测用于判断理解、惊喜与持续游玩意愿，不作为当前无人开发的停工条件。
