## 证据分级

| 标识 | 可以证明什么 | 不能扩大为 |
| --- | --- | --- |
| `measured` | 本轮实际运行或操作的特定断言 | 未执行平台、玩法或真人结论 |
| `static` | 源码、类型、清单或磁盘制品检查 | 实际用户交互、首屏网络流量 |
| `not-run` | 本轮没有足够执行证据 | `passed`、零错误或“不适用即通过” |
| `failed` | 断言失败、身份过期、证据缺失/损坏 | 可发布 |

每次验收绑定 `runId`、`sourceHead`、包含未提交实现文件的 `sourceTreeDigest`、`profileSha256`、实际静态目录的 `buildHash`。没有 v2.12 静态目录时，`buildHash` 为 `null`。源码、profile 或制品改变后旧结果失效；必须重新执行，不能复制 v2.11 的绿色结果。

## 本轮运行顺序

冻结快照只建立一次，随后只检查：

```powershell
npm run baseline:v212 -- --check
```

当源码、类型与新测试已准备好时，再执行构建。以下命令会重建当前开发输出 `apps/web/out`，但不会写入任何旧 ZIP：

```powershell
npm run build:v212
npm run audit:v212:check -- core
npm run audit:v212:check -- integrity
npm run audit:v212:check -- typecheck-core
npm run audit:v212:check -- typecheck-web
npm run audit:v212:check -- frozen
npm run audit:v212:static
npm run generate:v212:recipes
npm run verify:v212
```

`build:v212` 会记录实际构建输出并初始化当前验收身份。`audit:v212:init` 仅重建身份记录，不执行测试；修改源码后不能靠重新初始化继续使用旧证据。`verify:v212` 在必需证据缺失时以非零状态退出，这是预期的失败关闭行为。

## 真实 UI 调查要求

配方位于 `output/v212/flow-recipes.contains-spoilers.json`，包含解答后的公开文案及正确操作顺序，禁止用作宣传图或盲玩材料。编译器可以读取作者答案来生成测试步骤，但执行浏览器的代理只使用可见标签与角色定位：

- 不注入已解存档或 IndexedDB；不注入 Worker 命令；不读取隐藏运行状态。
- 开场先检查零提问曝光，再查看解答配方。
- 从场景、自然提问、歧义确认与刷新、证据检查、错误理论、证明缺口，实际操作到结案、回放和再次刷新。
- 每步记录执行动作、实际观察、时间、截图或可见 DOM 记录的 SHA-256。不能只有目标步骤清单。
- 三引擎、两种视口逐项记录；不可用引擎保持 `not-run`。

收据契约见 [v212-browser-contract.ts](../tools/lib/v212-browser-contract.ts)。这是已知答案的 UI 可行性验收，不能伪称合成玩家独立发现了答案，更不能伪称真人盲测。

## 离线、性能与 UI 边界

v2.12 继续完整预缓存，而不是声称首次只下载当前案件。磁盘预算、预缓存计划字节、真实冷启动网络流量与交互延迟分别报告。可选 AI 默认关闭、无网络和无 Key 均不应影响确定性核心通关。

UI 的目标是让主操作、证据来源和错误恢复直接可读：提高文字与触控目标尺度、避免重复候选、保持草稿与选择、修复主题变量和无效操作。44px 是本项目选择的增强触控目标，不是所有 WCAG AA 控件的硬性尺寸。设计来源与要求边界见 [设计依据](./v2.12-design-sources.md)。
