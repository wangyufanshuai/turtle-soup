# TURTLE SOUP v1.7 · 外部推理游戏设计证据

检索日期：2026-08-24
检索方式：Exa，4 个检索方向、32 条结果审阅；以下保留三份与 v1.7 直接相关的开发者/实践者来源。

## 结论

- 复杂推理需要局部进度反馈，但反馈不能替玩家宣布答案。
- 提示应由玩家主动请求，并逐层增加具体度。
- 调查系统可以提供很多信息出口，但玩家提交结论的入口必须少而连贯。
- 只保留必要线索与有趣误导；数量本身不是调查深度。
- 自动求解与一致性测试不能替代真人对理解、节奏和满足感的判断。

## 来源与采用方式

1. [The Case of the Golden Idol developer interview](https://www.gamedeveloper.com/design/case-of-the-golden-idol)
   - 采用：让玩家组织结构化结论；在复杂证明中提供局部闭合状态。
   - 不复制：填词格式、世界观、角色或视觉资产。

2. [Detective Game Design: Puzzles vs. Story — Lacuna devlog](https://www.gamedeveloper.com/design/detective-game-design-puzzles-vs-story-lacuna-devlog-)
   - 采用：调查信息可以丰富，但结论提交必须收束；错误反馈保留推理空间。
   - 不复制：对话结构、叙事分支或案件设定。

3. [Toby's Nose postmortem](https://intfiction.org/t/tobys-nose-postmortem/8470)
   - 采用：提示主动触发、渐进披露；观察文本只承载值得推理的信息。
   - 不复制：交互小说命令体系或原作内容。

## 对 v1.7 的直接约束

- 三级提示固定为“概念方向 → 证据类别 → 证明义务类型”。
- 提示不出现事实 ID、证据 ID、内部事件 ID、标准下一问或正确事件顺序。
- 多板案件默认只突出当前任务；已闭合板可折叠，但统一提交仍验证全部义务。
- 预算型合成玩家允许放弃，不能用穷举通关率冒充合理体验。
- 报告状态保持 `internal-rc / human-evaluation-pending`，真人参与为 `0`。
