# v2.12 C01 public-copy review

## Scope and outcome

This is an author-side review of the nine C01 question labels, not an 84-case semantic rewrite or a human playtest. Six labels are corrected only in `content/zh/presentation/v2.12/patches.json`; three are retained. Every replacement is an exact phrase already present in the frozen C01 `questionSemantics.examplePhrases`. No new aliases, predicates, facts, answers, evidence gates, proof obligations, canonical identities, or case semantics are introduced.

The selected profile must be exactly `v2.12-internal-rc`. Registry generation merges v1.4, then v1.7, then this v2.12 overlay. Historical and other profile names, including a later-version name, do not select it. The other 83 selected cases retain their existing presentation patches. C01 presentation revision advances from 3 to 4; its content version and canonical hash remain unchanged.

## Findings and disposition

All nine old labels already route exactly under the selected v1.6 + v1.7 alias packs. The defect is therefore **successful routing with misleading public interpretation**, not a missing parser rule. In particular, a `no` answer to “is it a person knocking?” must not be displayed as a denial that the sound came from inside the room.

`Code` below means the frozen `answerCodeWhenVisible`, not a promise of an immediate answer before evidence is available.

## Compatibility issue discovered during review

`createQuestionRoutingOffer` hashes the ordered public candidate labels into its `contextHash`. Therefore even an unchanged door question saved as a legitimate v2.11 `ask_resolved_text` command becomes stale after another C01 label changes. The additional regression constructs that command using the actual v2.11 patched/aliased case, confirms it replays under the old copy, and requires successful v2.12 historical replay with unchanged schema-one command bytes. It also requires the live reducer to keep rejecting the old context hash.

At the initial reproduction, the new compatibility test failed with “存档第 1 个操作无法重放；原存档已保留。” while the other 13 alignment checks passed. The separate core compatibility implementation now accepts explicit historical routing context only in `replayCommands`; the public live reducer receives no compatibility option.

Registry source now exports the read-only `selectHistoricalQuestionRoutingContexts` selector. For exactly v2.12 and C01, it reads and parses the frozen C01 case plus v1.4/v1.7 presentation and v1.6/v1.7 alias files once, verifies their pinned SHA-256 values, validates the old overlays, and captures only identity and ordered public candidate fields. There is no fallback to current presentation or aliases. It emits an empty map for other profiles and omits the unchanged 83 cases. The eventual generated `historical-question-routing-registry.ts` is worker-only; no truth graph, answer codes, proof rules, or certificate is included.

After that integration, the old-copy-to-new-copy regression passes using the same read-only selector as production generation. It verifies historical replay success, unchanged schema-one saved bytes, and continued live rejection of the stale hash. A further selector test checks C01-only/profile-only scope and absence of truth-bearing fields. Final focused result: **15/15 alignment tests and the existing presentation-patch test passed, 16/16 combined**. Core TypeScript no-emit and `git diff --check` also passed. This does not by itself establish generated-worker or browser behavior.

The historical-save oracle intentionally compares the old presentation layer on both sides. It is not modified to hide this issue and does not replace the explicit old-copy-to-new-copy regression.
